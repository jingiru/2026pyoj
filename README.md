# 2026pyoj
파이썬 수업용 OJ

## 개요

PyOJ Classroom은 중학생 파이썬 초급 수업을 위한 Online Judge 기반 학습 플랫폼입니다.

- 학생: 학번 4자리와 이름으로 로그인하거나 비로그인으로 문제 풀이, 코드 제출, 결과 확인
- 교사: 제출 기록 확인, 학급 대시보드, 문제 생성 흐름 확인
- DB: Supabase PostgreSQL
- 배포: Vercel

## 실행

```bash
npm install
npm run dev
```

브라우저에서 `http://127.0.0.1:3000`으로 접속합니다.

Supabase 환경변수가 없으면 브라우저 저장소를 사용해 데모 모드로 동작합니다.

## Supabase 설정

1. Supabase 프로젝트를 생성합니다.
2. SQL Editor에서 `supabase/schema.sql`을 실행합니다.
3. Vercel 또는 로컬 `.env.local`에 아래 값을 등록합니다.

```bash
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
TEACHER_PASSWORD=...
SUPABASE_SERVICE_ROLE_KEY=...
```

최신 Supabase 프로젝트에서 publishable key를 제공하는 경우
`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 대신 사용할 수 있습니다. 환경변수를 변경한 뒤에는
Vercel에서 새로 배포해야 클라이언트 번들에 값이 반영됩니다.

`TEACHER_PASSWORD`와 `SUPABASE_SERVICE_ROLE_KEY`는 서버 전용 값입니다. 두 값에는
`NEXT_PUBLIC_` 접두사를 붙이지 마세요. 기존 Supabase 프로젝트는 SQL Editor에서
`supabase/teacher_dashboard_security.sql`을 한 번 실행해 브라우저 anon 사용자의 제출 기록
조회 권한을 제거합니다. 교사 대시보드는 인증된 서버 API가 service role로 조회합니다.

비로그인 문제 풀이를 배포하기 전 기존 프로젝트에서는 SQL Editor에서
`supabase/guest_access_migration.sql`을 한 번 실행하세요. 비로그인 사용자는 브라우저별
임의 토큰으로 구분되며 `students.guest_token`, `students.last_ip`에 토큰과 IP 주소가
원문으로 저장됩니다. 두 값은 개인정보 및 게스트 접근 권한 정보이므로 students 테이블은
브라우저 anon 역할에서 조회할 수 없도록 유지됩니다.

처음 설치하거나 문제 테이블이 비어 있는 프로젝트는 Supabase SQL Editor에서
`supabase/seed_current_curriculum.sql`을 실행해 현재 앱의 문제집, 문제, 테스트케이스를
등록해야 합니다. `submissions.problem_id`는 `problems.id`를 참조하므로 문제 데이터가 없으면
학생 제출 저장이 외래키 오류로 거부됩니다.

기존 DB에서 문제 일괄 업로드를 사용하기 전에는 SQL Editor에서
`supabase/problem_bulk_import_migration.sql`을 한 번 실행하세요. 이 SQL은 사용하지 않는
`problems.unit`, `problems.level` 컬럼을 삭제하고, 모범답안 저장 구조를 준비하며, 기존 영문
ID 제약조건을 제거한 뒤 문제집 ID를 `01 출력 함수 기초`와 같은 업로드 서식의 한글 ID로
이전합니다.

제출 데이터가 많아져 교사 대시보드가 느려진 경우 Supabase SQL Editor에서
`supabase/dashboard_performance.sql`을 한 번 실행하세요. 대시보드는 초기 조회에서 제출 코드와
피드백을 제외하고, 교사가 제출 셀을 클릭할 때 해당 학생·문제의 이력만 별도로 불러옵니다.

교사 화면의 문제 관리 영역에서는 XLSX 서식을 내려받고 문제를 일괄 업로드할 수 있습니다.
동일한 문제ID는 수정되고 새로운 문제ID는 추가되며, 완료 후 DB에서 문제·테스트케이스·모범답안
수를 다시 확인한 결과가 팝업으로 표시됩니다.

로그인 오류에 `42P01`, `42501`, `42703` 같은 코드가 표시되면 각각 테이블 없음, RLS/권한
문제, 컬럼 불일치를 뜻합니다. 브라우저 개발자 도구 콘솔에는 Supabase의 상세 오류도 기록됩니다.

## 챌린지 (수행평가 및 프로그래밍 대회)

홈의 챌린지 카드 또는 상단 챌린지 메뉴에서 시작합니다.

- 학생: 입장코드 8자리, 학번 4자리, 이름을 입력하면 대기실에 입장합니다. 교사가 시작하면 문제 설명과 IDE가 열립니다. AI 도움 아이콘은 챌린지에서 제공하지 않습니다.
- 교사: 같은 팝업의 **교사 관리**에서 `TEACHER_PASSWORD`로 인증합니다. 기존 문제(비공개 포함)를 선택하고 순서와 제한시간을 정해 입장코드를 생성합니다. 문제를 비공개로 준비하려면 기존 교사 화면의 문제 관리를 이용합니다.
- 회차마다 문제와 테스트를 복사해 저장하므로 기존 문제 수정이 진행 중인 평가에 영향을 주지 않습니다. 수행평가에 사용할 새 문제는 일반 문제 관리에서 비공개로 저장하세요. 이미 공개된 문제를 선택해도 기존 공개 상태가 자동 변경되지는 않습니다.
- **시작**은 전체 학생에게 동시에 적용되며 늦게 입장해도 마감은 같습니다. 종료 후 **시간 추가 후 재개**를 누르면 현재 시각부터 추가 시간이 적용됩니다. 시작·연장 이력이 보관됩니다.
- 교사는 학번·이름별 문항 정답, 제출 횟수, 최초 정답까지 걸린 시간, 문항 최초 해결자(★), 제출 코드를 확인합니다. 정답 수가 같으면 공동 순위입니다. 대회용으로 학생에게 순위를 공개할 수도 있습니다.
- 제출은 서버와 DB가 마감과 참가 권한을 확인하고 코드를 접수한 후 서버에서 채점합니다. 마감 전에 접수한 제출은 채점이 마감 후 끝나도 인정됩니다. 학생이 보낸 채점 결과는 사용하지 않습니다.
- 작성 코드는 회차·참가자·문항별 브라우저 저장소에 보관합니다. 같은 브라우저에서 새로고침하거나 문항을 바꾸어도 복원됩니다. 같은 회차에서 학번과 브라우저는 하나의 참가 기록에 연결되므로 재입장도 처음 사용한 브라우저에서 진행하세요. 저장소/쿠키 삭제나 다른 기기로의 이동은 코드 복원 대상이 아닙니다.

### 설치와 운영

기존 환경변수 `TEACHER_PASSWORD`, `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 사용합니다. 로컬 데모 저장소는 여러 학생의 평가와 공통 타이머를 보장할 수 없어 챌린지에는 사용하지 않습니다.

새 DB에는 `supabase/migrations/20260906004213_challenge_mode.sql`을 한 번 적용하세요. 이 작업에서 연결된 `DB-pyoj` 프로젝트에는 적용을 완료했습니다. 로컬 파일 버전은 실제 DB 적용 이력과 맞췄습니다. 챌린지 테이블 4개와 제어 함수 2개는 RLS를 활성화하고 브라우저 역할의 접근을 차단했으며 서버 전용 키로만 사용합니다.

챌린지 채점기는 설치된 Skulpt를 별도 Node worker에서 실행합니다. 초급 Python 문법을 지원하며 CPython 전체 표준 라이브러리를 제공하지 않습니다. 제출 코드 20,000자, 출력 64KB/테스트, 테스트 실행 1.5초, 제출 전체 12초 및 worker 메모리 제한을 적용합니다. 채점의 동시 실행은 참가자당 하나로 제한합니다. 대규모 대회에는 별도 채점 큐와 격리 실행 서비스가 필요합니다.

### 검증

`npm test`는 기존 실행기 및 순위 테스트와 챌린지 시간 경계·정보 비공개·권한·서버 채점·동시 실행 테스트를 실행합니다. `supabase/tests/challenge_mode.sql`은 설치된 DB에서 시작/종료/연장/중복 제출/RLS를 확인한 뒤 검증 데이터를 전부 롤백합니다. `npm run build`로 배포용 빌드를 확인한 후 `npm run test:challenge-build`를 실행하면 실제 빌드된 Next 서버와 채점 worker를 검증합니다. 이 검증은 DB 통신만 로컬 모의 서버로 대체하므로 운영 학생 데이터에 영향을 주지 않습니다.

## 일반 문제 풀이 채점 설계

Vercel 서버리스 함수에서 학생의 임의 파이썬 코드를 직접 실행하지 않습니다. 실제 운영 채점기는 Judge0, Piston, Docker 기반 샌드박스, 별도 채점 서버 중 하나로 분리하는 것이 안전합니다. 현재 구현은 초급 예시 문제를 체험할 수 있는 교체형 판정 모듈을 사용합니다.
